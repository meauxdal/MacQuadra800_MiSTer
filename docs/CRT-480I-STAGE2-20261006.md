## Implementation and stream contract

`rtl/tv525_output.sv` connects the unchanged Stage 1 timing and diagnostic
patterns to `tv_osd`, `tv_component`, and `tv_component_pins`. All remain
outside production QSF/QIP filelists. There is no Mac clock/input, DDR access,
Intel primitive, or clock mux in this wrapper. Pattern/geometry inputs must
remain constant for a pair; future platform controls need their own mailbox.

Electrical field 1 still draws odd canvas rows and electrical field 2 even
rows. `frame_start` denotes the first temporal field, not parity zero.
The authoritative equalizing/serrated composite waveform comes directly
from `tv525_timing`; neither OSD nor conversion reconstructs it from HS/VS.

Every sample carries a 29-bit tag through the same pipeline as RGB:

| Tag bits | Meaning |
| --- | --- |
| 28, 27, 26 | Active-low composite, horizontal helper, vertical helper sync |
| 25, 24, 23 | Picture DE, first-sample pixel CE, spatial field parity |
| 22, 21, 20, 19 | Frame, field, line, half-line markers |
| 18:9, 8:0 | Canvas x, y |

The OSD takes two register stages (clocked bitmap read then composition).
Conversion takes three (per-channel products, sums, quantization). At a
rising edge the output represents the input sampled on the fourth previous
edge: five registers total, conventionally a five-sample pipeline. All
sync, DE, CE, coordinates and markers share this delay. Reset clears the
pipeline to inactive sync and no DE; the component code becomes `800080`.
Asserting pipeline reset interrupts a live raster, so platform integration
must use startup/PLL reset rather than guest reset for this free-running path.

## OSD and host transport

`tv_osd` reuses the `sys/osd.v` bitmap layout and 0x2x write / 0x4x control
protocol. The 4,096-byte dual-clock bitmap stores 256 columns by 128 rows;
address is `(row/8)*256+column`, selected bit is `row%8`. One command byte
is followed by data words, accepted on rising `io_strobe` while `io_osd`
is asserted. Writes outside the 4,096-byte region are ignored.

The menu is 256x64 bitmap pixels, or 256x128 after a high-resolution page
write. It is centered in the canvas and displayed at 2x2 logical pixels per
bitmap pixel. Each field therefore sees one row of every doubled bitmap
row: text is present in both fields, independent of source geometry or loss.
The bitmap colors use the framework's default red tint and background
attenuation. That tint is intentional OSD composition, not a CRT diagnosis.

Info mode accepts x/y, width/height in multiples of eight, and rotation from
the control transaction. Coordinates are in bitmap units, scaled by two;
rectangles clip to the logical canvas. Width/height cap at 256/128. Rotation
0/1/2/3 is 0/90/180/270 degrees clockwise. A rotated centered menu has a
512-pixel logical height: it starts at y=0 and clips its bottom 32 pixels.
This explicit TV policy differs from the framework's resolution estimation;
normal menus default to rotation zero. MENU_CORE's optional header is not
implemented for this Quadra wrapper.

Configuration is a held request/acknowledgement mailbox. Host updates publish
only after `io_osd` deasserts; the payload cannot change until acknowledged.
The request and acknowledgement each cross two synchronizer registers.
The receiver adopts the entire payload only at `frame_start`, retaining
one configuration for both fields. Changes while a request is pending are
sent after its acknowledgement, so the latest completed configuration
eventually arrives. This can take additional pairs; transport latency is
deliberate and not an immediate OSD update guarantee.

`osd_status` remains a host-domain status output matching the ordinary
menu/info enable semantics. Both mailbox endpoints must reset together;
reset release must be synchronized independently in each domain. Constraints,
metastability, and physical CDC implementation remain synthesis/fit work.
Bitmap contents are not reset. Upload while disabled for static diagnostics;
live writes may be visible during a pair, and simultaneous same-address
dual-clock RAM read/write is unspecified. This is configuration coherence,
not double-buffered OSD memory. No full-frame Mac image buffer is involved.

## Conversion and digital lane adapter

`tv_component` translates the existing `sys/vga_out.sv` shift/add arithmetic
without changing the production converter. With 8-bit R/G/B:

```text
Y  = floor((77R + 150G + 29B)/256)
Pb = floor((32768 - 42R - 85G + 128B)/256)
Pr = floor((32768 + 128R - 106G - 21B)/256)
```

Signed intermediate values are widened and saturated before quantization.
Electrical blanking forces RGB zero before conversion, producing Y=0 and
neutral Pb=Pr=128. Picture borders remain inside DE and also convert to
black/neutral. These are the existing framework's full-range digital codes;
they do not by themselves specify voltage or insert negative sync into Y.

`tv_component_pins` maps `{Pr,Y,Pb}` to R/G/B upper-six and lower-two digital
DAC lanes. HS carries delayed active-low authoritative composite sync and VS
is inactive. `av_dis` supplies a drive-enable request; top-level platform
pins must implement tri-state behavior. Video disable supplies black/neutral
codes and inactive sync. This adapter does not drive physical pins or resolve
analog-board sync-on-Y insertion, SD sharing, or resistor DAC levels.

The wrapper bench uses only public stream ports and the separately generated
host bitmap. It compares every electrical sample during qualified captures,
including repeated DAC samples and both first/last picture edges. Conversion
is additionally checked against actual compositor samples throughout the
entire run, even while configuration is settling. Tag comparison verifies
every pipeline pulse edge. The standalone converter oracle uses integer
matrix multiplication rather than the RTL shift/add implementation.

The OSD transition monitor requires every pixel in a complete pair to belong
to one whole old/new configuration. The negative mutation check demonstrates
that intermediate configuration tuples cannot pass this check. The mutation
source/results are isolated under ignored `scratch/tv525_stage2_mutation/`;
the production standalone RTL retains transaction-close gating.

and the 90-degree info image over black. The renderer preserves pixel values
and exports each spatial parity separately. RGB images show composition
before conversion; they are not predictions of the CRT's colors/voltages.
