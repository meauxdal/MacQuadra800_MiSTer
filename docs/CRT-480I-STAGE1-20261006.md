# CRT 480i Stage 1: independent raster and diagnostics

Implemented and verified on 2026-10-06 against the
[engineering plan](CRT-480I-ENGINEERING-PLAN-20261006.md). Base checkout:
`157CRT`, `bb8db1eb4c7fb752f53cdf07e6f1eb66318e31d4`; changes are uncommitted.
No existing Mac RTL, analog routing, PLL, QSF, QIP, SDC or build stamp was
changed. No Quartus flow or MiSTer action was performed.

## What is implemented

- `rtl/tv525_timing.sv`: a free-running 27 MHz sample-domain raster with
  1,716 samples per line, 262.5 lines per field and 525 lines per pair.
  Horizontal phase continues across field boundaries. Authoritative
  active-low composite sync includes six pre-equalizing, six serrated broad
  vertical, and six post-equalizing pulses in each field. HS and VS are
  separate helper signals, not the formula for composite sync.
- The logical picture is 640x480. Electrical lines 23-262 draw odd logical
  rows; lines 285-524 draw even rows. A 1,422-sample horizontal aperture holds
  each logical pixel for two or three DAC samples using an accumulator.
  `pixel_ce` marks the first sample of each logical column, while
  `picture_de` stays active throughout the aperture, including image borders.
- `rtl/tv_test_pattern.sv`: black, white, grayscale ramp, 75% bars, grid and
  circle, field patch, alternating lines, and a source-coordinate signature.
  Its three geometry choices exercise 640x480, centered 512x384 at (64,48),
  and centered 512x342 at (64,69). Reserved geometry 3 falls back to 640x480.
  This is synthetic picture generation; it does not implement Mac capture.
- `verilator/tv525_diagnostic.sv`: a simulation wrapper connecting the two
  modules. Their inputs do not include a Mac clock or source-frame event.

All stream outputs are combinational functions of TV-domain state. Reset
is synchronous for the counters and blanks sync/picture/markers while high;
the integrating wrapper must release it in the TV clock domain. Pattern and
geometry controls must be held for a complete field pair or latched by a
future wrapper at `frame_start`. Later RAM, OSD, and color-conversion stages
must delay sync, DE, CE and coordinates with the pixels.

The new modules are intentionally outside the Quartus file lists until the
component wrapper is ready. Running the existing project's synthesis now
would not establish their FPGA resource use or timing.

`tb_tv525.cpp` uses a complete-frame pulse-event table and absolute electrical
line labels as its timing reference. It neither reads DUT counters nor
imports RTL constants. It compares `csync_n`, HS/VS helpers, DE, field ID,
markers, coordinates, logical pixel enable, source rectangle, and RGB at
every electrical sample. Its coordinate oracle uses direct division while
the RTL sampler uses an accumulator. Each pair must cover every logical
canvas position exactly once, preventing repeated/missing rows or columns
from being hidden by the woven reconstruction.

The initial plan incorrectly assigned even image rows to electrical field 1.
[ITU-R BT.1618 section 5.1.2](https://www.itu.int/dms_pubrec/itu-r/rec/bt/R-REC-BT.1618-0-200305-S!!PDF-E.pdf)
assigns odd image rows to field 1 and even image rows to field 2 for the
selected aperture. The implementation, plan and reference were corrected.
The bench additionally derives vertical row position from elapsed time since
the field sync origin: row 0 begins at 21.5H in field 2; row 1 at 22H in
field 1. This check would reject a swapped spatial pair even if a software
weave reconstructed an apparently correct grid.

The 342-line reference naturally requires source row 0 in the odd canvas
field and source row 1 in the even field. Both fields contain 171 source
rows. Its border boundaries, channel high bits, and last source row are
covered by the full pixel comparison, not only a first-pixel parity check.

`render_tv525.py` separately measures pulse widths and intervals in the
exported VCDs, then converts the binary PPM reconstructions to PNG without
changing pixels. The four `steady*_sync.vcd` files start just before
the field-origin edge, so the first pulse is not cropped. Each window spans
the vertical sequence and its return to ordinary sync. Picosecond trace
timestamps represent an ideal 27 MHz clock; they do not measure an oscillator.

Visually inspected the full grid/circle and the centered 342-line coordinate
reconstruction. Both fields reconstruct one correctly ordered picture.

## Reproduction and artifacts

From the repository's `verilator/` directory in WSL/Linux:

```sh
verilator --lint-only --Wall --top-module tv525_diagnostic \
  tv525_diagnostic.sv ../rtl/tv525_timing.sv ../rtl/tv_test_pattern.sv
make tb_tv525
```

The target performs compile, simulation, waveform audit, and rendering. Use
`TV525_OUT=<directory>` to select another artifact directory. No ROM, disk,
SDL, Quartus, network connection, or Python package installation is needed.
The C++ bench needs C++17 and Verilator's VCD support. Python rendering uses
only its standard library. The current default artifact directory alone is
ignored by Git; the source and report remain reviewable.

Useful local artifacts:

- `verilator/out/tv525/verification.txt`: counted simulation results.
- `verilator/out/tv525/waveform_audit.txt`: measured trace results.
- `verilator/out/tv525/source_manifest.json`: SHA-256 of the six source/build
  files used to reproduce the bench and renderer.
- `verilator/out/tv525/gallery.html`: all woven frames and separate fields.
- `verilator/out/tv525/g0_grid.png`: full-canvas geometric diagnostic.
- `verilator/out/tv525/g2_white.png`: the 512x342 placement and borders.
- `verilator/out/tv525/g2_coordinates_field0.png` and `...field1.png`: source
  coordinate signatures in each field's native row order.
- `verilator/out/tv525/sync_edges.csv`: sync/DE edges for the first four fields.
- `verilator/out/tv525/steady*_sync.vcd`: current steady-field sync captures.
- `scratch/tv525_stage1_build.log`: local compilation/simulation log.

Older `field*_sync.vcd` and `window*` files from the initial local runs may
also be present; the renderer audits only the corrected `steady*` captures.

## Limits and next step

Stage 1's digital gate passes. This does not prove PLL legality, synthesis
area, FPGA timing closure, DAC amplitude, component color, or CRT field
placement. There is no component conversion, OSD integration, DDR access,
Mac capture, or hardware output in this stage. The existing CRT experiment
and normal Mac path are unchanged.

Update: the [standalone Stage 2 digital wrapper](CRT-480I-STAGE2-20261006.md)
now passes simulation; production integration and analog qualification remain.

The Stage 2 direction is to adapt the TV stream to component conversion and usable
OSD, with all controls delayed together. Before pin-level routing and a
hardware test, identify the analog board/revision and effective component/
SoG settings for the passive MiSTer Addons cable. Then add the new profile
to the FPGA sources, inspect inference and constraints, and fit with the
single-flow build policy. A hardware load still requires the user's
authorization and a fresh menu/safe-shutdown state check.
